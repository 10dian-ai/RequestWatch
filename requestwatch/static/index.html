GET CONNECTED

接入指南.

Web 操作台位于 7030 端口。根据协议选择对应的流量接入方式。

01 / HTTP & HTTPS

配置代理，查看解密后的请求

将目标程序或 Docker 容器的 HTTP_PROXY / HTTPS_PROXY 指向 RequestWatch 服务器的代理端口（默认 8080）。

HTTP_PROXY=http://<服务器IP>:8080
HTTPS_PROXY=http://<服务器IP>:8080

在目标程序的信任库中安装 RequestWatch CA 后，才能查看及修改 HTTPS 明文。容器内的 localhost 指向容器自身，请使用可达的宿主机地址。

代理默认监听 127.0.0.1。容器或远程程序接入前，在「项目设置」中将代理监听地址改为可达地址；开启代理认证后，目标程序还需提供代理用户名与密码。

代理启动后可下载证书。证书固定、独立信任库、忽略代理设置的程序需要另行适配。证书不会自动安装到目标设备。

02 / TCP & UDP

启用 Ubuntu 抓包与暂停

在 Ubuntu 上以 root 运行捕获引擎，使用 NFQUEUE 接收本机与 Docker 转发的网络包。安装和启动命令见项目 README。

  • 捕获的数据包可以按文本、协议、端口和容器搜索；「TCP 会话」可按连接查看及搜索双向全文。
  • 创建规则后，命中的数据包会进入「拦截队列」。
  • 放行前可编辑载荷，TCP 必须保持字节长度不变。
  • 非 HTTP 的 TLS 和其他加密流量只能查看密文字节；原始包不等同于完整应用请求；会话视图会标出缺包、缺少握手和未结束状态。
重发 TCP 载荷会建立新连接；重发 UDP 会发送新数据报。它们不会恢复原连接状态，协议握手和认证仍可能影响结果。
03 / INTERCEPT

只暂停你关心的流量

按容器、目标主机或 IP、端口和关键词组合建立规则。先使用窄范围规则验证，再扩大匹配范围。

SSH、工作台和代理端口的保护范围由后端控制。默认保护端口：22、7030、8080。
